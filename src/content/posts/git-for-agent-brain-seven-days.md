你有没有遇到过这样的事：一个 AI 助理，教过它的东西，过几天又做错了。或者它某天说话的方式突然变了、办事的流程变了——你确定没人动过它的提示词。

那是它自己改的。

这一代 agent 不是聊天机器人，是会长期工作、顺手修改自己的系统：把学会的套路写成技能文档，把新认识的事实记进记忆文件，把不顺手的流程改成新的脚本。我们在自己团队真用一个这样的 agent（Hermes，Nous Research 出的，跑在我们的 Mac 上，每天凌晨扫描团队群聊建任务台账、早上八点发日程简报、盯开源仓库、写周报），用的这一个月里，它自己改自己的次数，比我们所有人加起来还多。

于是它变成了一类很新的软件：**会自我改写，却说不清自己为什么变成现在这样。**

给它讲一句"不对，以后别这样"，它当场改了——但没人知道它改的是哪份文件、改动什么时候生效、会不会把另一个流程碰坏。它改坏了东西，也没有任何一个"退回上周三"的按钮。

我们做的事说起来毫不稀奇：给它装了一台监控摄像头，加一台时光机。实现方式是一个 `git init`。

## 一个 git init，凭什么

把整个 `~/.hermes`（agent 的家目录）变成一个 Git 仓库，推到私有远端，写一份 `.gitignore`，立三条纪律——这就是全部工程。一个运行中的产品，不用改它一行代码，Git 就挂上去了。

轻，是因为它的大脑恰好是一堆 Markdown。但这个说法只对了一半——"纯文本"不是答案，GitHub 上被单个两兆 JSON 折磨的仓库多的是。真正让它兼容 Git 的，是它目录里混着的三类东西，命运完全不同：

**第一类：行为输入。**技能文档、记忆、人格设定、自动化脚本、提示词配置。这是 agent"决定怎样工作"的部分——纯文本、一个文件大致对应一种能力、改得少但每次改动都值得说清楚。这类进 Git，共 2113 个文件，九成是技能。

**第二类：运行事实。**会话数据库（1.1 GB 的 SQLite，每条消息、每次工具调用、每把锁）、日志、缓存。这类改动每秒发生十次，每一行都没有单独留史的意义，而且它们有一致性协议——官方自带升级快照和数据库感知的备份命令，那是 SQLite 事务的世界，Git 闯进去只会帮倒忙。这类永远不进仓库。

**第三类：凭据。**密钥、token、登录态。这类进哪一类都不行，死都不进——而且这条线最后证明是最难守的，后面有故事。

判断一个文件该不该进 Git，就问一句：**它是 agent"决定怎样工作"的部分，还是它"工作留下了什么"的部分？**前者是版本化的对象，后者是备份的对象，两个世界各归各的协议。

这个过滤器划好之后，剩下的就是一台时光机的日常运转。七天，76 个 commit。

## 时光机的三次显灵

**54 秒的复活。**官方升级会把自己的代码仓库重置到上游，我们在适配层打的两个定制补丁一夜被抹平。翻历史找回那两个 commit，两条 `cherry-pick`，reflog 的时间戳相差 54 秒。（诚实的边界：54 秒是仓库里的时间窗，整个恢复流程——发现、验证、重启服务——花了更久；而且这个场景救火的是代码仓库的 Git，我们外层数据仓库的价值，是让"该用哪份补丁恢复、为什么"作为知识躺在历史里，而不是散落在某个人的脑子里。）

**谁改了它的语气。**某天一条自动消息的措辞不对劲。`git log` 五分钟：9 月 4 日凌晨的一次跑批任务改了追问话术，commit message 里写着为什么改。没有人需要回忆，也没有人事后背锅。以前这叫"玄学 debug"，现在这叫查表。

**最意外的一用：commit message 成了 agent 的外置长期记忆。**我们约定机器每天收尾把资产变更记一次快照，且人话写清楚为什么改。后来发现，新会话里的它读自己家目录时，会把这份历史当材料读——它现在知道"自己为什么是现在这样"。一个给人类设计的机制，喂饱了机器的失忆症。

## 时光机的三次翻车

同一批七天，敏感信息三次差点或真的流进仓库。这段是本篇存在的理由：只讲收益的文章，都是没摔过跤的文章。

**历史里翻出密钥。**建仓库、推远端之前做全历史扫描，发现一份业务快照里躺着一把真实可用的 API 密钥——它进目录时 Git 还不存在，是"第一次版本化"把它照了出来。处置是三步：移出跟踪、`filter-repo` 重写全历史（几十个 commit 换哈希、强推覆盖远端）、然后才是真正要紧的那步：**去服务端轮换这把 key**。删除文件、清除历史、作废凭据，是三件事，漏一步都不算完。

**清掉的东西自己回来了。**一类内部备份文件我们八月底就移出过跟踪、写了 ignore 规则。第二天，它们回来了，两百多个文件——规则写漏了路径，而每天自动"全部提交"的纪律，忠实地把它们重新收进了仓库。自动化没有价值观，你写歪的边界它执行得最认真。

**守夜人自己越界。**每天六点的例行体检里有一项敏感扫描，实现方式是"遍历家目录"。它遍历了什么？几乎全部——包括那份约定谁都不许读的配置。相当于我们雇了个机器人，每天定时把最敏感的文件读进一个会被上报的上下文。铁律没被外人破，被自家守夜人破了三周。修法：扫描改白名单目录，并在测试里写死"扫描器不得越界"。

三次事故提炼成一句话，也是这篇最想说的一句：

> **Git 让 agent 更容易恢复，也让它的秘密更难消失。**

资产的每一次改进和每一次误入库，用的是同一套"忠实复制、永久留存"的机制。版本化是一台双刃的时光机。

## 所以这是架构，还是 Hack？

我的判断：**有纪律的外挂是正当架构，没纪律的外挂是定时炸弹**——而纪律这东西，恰好可以自动化：内容级敏感扫描、白名单边界、每日体检、升级前核对。把这四件事配齐，这个周末下午搭起来的旁挂方案，就可以长期用。

它也有一条体面的退路。翻官方仓库会发现，这条路不是旁门：Hermes 最近的版本里已经有 Profile Distribution——**用 Git 仓库作为来源、发布安装一整套 agent profile**；issue 区里"技能写入即提交"的讨论挂着，说明官方知道这个需求。分发这块已经被官方路线覆盖，本地资产的历史这块仍是空白。我们仓库未来的正确姿势是瘦身：发布交给官方协议，自己收敛成"受控资产源 + 演化历史"。方向是收敛，不是拆掉。

如果你也在跑一个会自己写技能、改记忆的 agent，大脑超过二十个文件、团队真的靠它干活——建议做，一个下午的事。三句前提：行为输入和运行事实分开管；自动提交纪律配好边界再开闸；接受它管不了的部分——它不能保证同样的 commit 重放出同样的对话，更不能当保险箱。

最后留一个我们没解决的问题。文件能回滚了，但**理解不能**：技能退回上周三是 `git checkout` 的事；"agent 对某件事的认知"退回上周三，今天没有任何工具做得到——记忆作为文本进了版本库，记忆作为认知，还活在每天的上下文压缩里，压过去就没了。

那是下一台时光机的事。
